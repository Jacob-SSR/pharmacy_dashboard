# การนับชนิดยาก่อนเรียกคนไข้

ตั้ง `PHARMACY_MANY_ITEMS=4`: 1–3 รหัสยาเป็นยาน้อย, ตั้งแต่ 4 รหัสเป็นยามาก, 0 รหัสไม่เข้าตะกร้า ส่วนผู้ป่วยเร่งด่วนยังเข้าตะกร้ายาด่วนและเห็นจำนวนชนิดยาในตาราง

ตารางเปิดที่รอเรียก เรียงชนิดยามากไปน้อย กดหัวชนิดยาเพื่อกลับลำดับ หรือกดการ์ดรอเรียกซ้ำเพื่อดูทุกสถานะ การ์ดตะกร้ารวมทั้งรอเรียกและเรียกแล้วที่ยังไม่รับยา

นับ `opitemrece` ตาม VN ของ `ovst.vstdate` ที่เลือก เฉพาะ OPD และรหัสที่มีใน `drugitems` รวมจำนวนตาม VN + icode ก่อน แล้วเก็บเฉพาะยอดสุทธิมากกว่า 0 ทั้งตารางและรายละเอียดใช้ SQL ชุดเดียวกัน ไม่ใช้วันที่บันทึกรายการยาเป็นตัวตัดรายการของ visit จำนวนทศนิยมยังคงเดิม วันที่เริ่มต้นใช้ Asia/Bangkok

อ้างอิง cashier_dashboard/lib/cashier.service.ts ที่ตรวจยาตาม VN และ ppc-hos-10667/lib/drugUsage.service.ts ที่แยก COUNT(*) ของบรรทัดออกจาก COUNT(DISTINCT icode) ของชนิดยา

## เทียบหน้างาน

1. ตรวจ `PHARMACY_DEPCODES` ให้เป็นรหัสห้องยาจริง และเปิดหน้าที่ขึ้นข้อมูล live
2. เลือกวันและ VN เดียวกับ HOSxP เปรียบเทียบรหัสยาและจำนวนในหน้ารายละเอียด โดยเฉพาะใบที่มียารหัสซ้ำและรายการคืนยา
3. ใช้ SELECT ด้านล่างกับบัญชีอ่านอย่างเดียว แทนวันที่และ VN ด้วยค่าที่ต้องการ ผลลัพธ์หนึ่งแถวคือหนึ่งชนิดยา จำนวนแถวต้องตรงกับหน้ารายละเอียด ณ เวลาเดียวกัน (รายการอาจเปลี่ยนระหว่างรีเฟรช)
4. ถ้ารายชื่อคนไข้ต่างกัน ตรวจแผนกและสถานะ visit ต่อที่ `/api/pharmacy/debug?date=YYYY-MM-DD` การแก้ครั้งนี้ยังคงกฎสถานะเดิม รวมถึงการตีความออกจากห้องยาเป็นรับยาแล้ว จึงต้องตรวจ flow หน้างานแยกจากจำนวนยา

```sql
SELECT op.vn, op.icode, SUM(COALESCE(op.qty, 0)) AS qty
FROM opitemrece op
JOIN ovst v ON v.vn = op.vn
WHERE v.vstdate = '2026-09-17'
  AND op.vn = 'VN_TO_CHECK'
  AND (v.an IS NULL OR v.an = '')
  AND EXISTS (SELECT 1 FROM drugitems d WHERE d.icode = op.icode)
GROUP BY op.vn, op.icode
HAVING SUM(COALESCE(op.qty, 0)) > 0;
```
